# 09 · 安全与隐私

## 9.1 信任模型

```
信任根 = 自建 ZeroTier 网络
         │
         ├─ 身份：网络成员身份（40 位 ZT 地址 + 密钥对）
         ├─ 加密：端到端，planet 也解不开
         └─ 授权：controller 的成员白名单（private=true）
```

**ztio 不引入新的信任根。** 它完全继承 ZeroTier 的信任模型：

| 问题 | 谁解决 | ztio 是否额外做 |
|---|---|---|
| 对端是谁 | ZeroTier 身份 | ❌ 不做 |
| 传输是否加密 | ZeroTier 端到端 | ❌ 不做 |
| 谁可以入网 | Controller 成员授权 | ❌ 不做 |
| **谁可以拿到我的局域网地址** | —— | ✅ **ztio 负责** |

**第四行是 ztio 唯一新增的安全边界**：候选集（含全部本地地址）是敏感信息，
只应该给**已入网的、你信任的**对端。

---

## 9.2 敏感信息清单

| 信息 | 敏感度 | 暴露途径 | 保护措施 |
|---|---|---|---|
| **局域网候选集** | **高** | 信令消息 | 只经 ZT 加密链路；不持久化 |
| **ZT 地址** | 中 | 花名册 | 花名册只在 ZT 网内可达 |
| 端口号 | 低 | 信令消息 | 同上 |
| 连接时间/频率 | 中 | 本地日志 | 日志不包含地址明文（可选） |
| 出口 IP | 低 | 对端可见 | 不可避免 |

## 9.3 威胁分析

### T1 · 陌生成员窃取局域网拓扑

**场景**：网络是 `private=false` 或有成员被入侵，恶意成员向你的设备发起信令会话，
骗取候选集（含你的全部内网地址）。

| 措施 | 效果 |
|---|---|
| **`private=true`**（强制） | 未授权成员无法入网，第一道防线 |
| 只响应**已知名字**的信令请求 | 拒绝未在花名册中的 peerName |
| 对端公钥固定（可选） | 首次连接时记录对端 ZT 地址，之后拒绝变化 |

> **`private=true` 是硬性要求。** 见部署手册。

### T2 · 信令重放

**场景**：攻击者重放旧的 `offer`，诱导你回连到已失效的地址。

| 措施 | 效果 |
|---|---|
| `seq` 单调递增检查 | 拒绝旧序号 |
| `gen` 版本检查 | 拒绝旧代数的候选集 |
| `sid` 会话标识 | 跨会话的重放直接失败 |
| **ZT 链路本身的加密** | 攻击者需要先能注入流量 |

### T3 · 降级攻击（Downgrade）

**场景**：攻击者阻断局域网探测，迫使连接长期走 RELAY，
从而让流量经过 planet（自建服务器仍可观测**元数据**：谁和谁在通信、流量大小）。

| 措施 | 效果 |
|---|---|
| 记录并上报降级原因 | **可检测**，不静默 |
| 数据面内容仍然端到端加密 | planet 看不到内容 |
| 定期重探测 LAN | 一旦恢复立即切回 |

> **注意**：planet 是自己部署的，所以这里的威胁是「服务器被入侵」而非「第三方观测」。
> 成本远低于使用公共基础设施。

### T4 · 权限滥用（探测被当作扫描）

**场景**：设备向 `/24` 全段发探测包，被网络管理员视为端口扫描。

| 措施 | 效果 |
|---|---|
| **只探测信令交换来的候选** | ✅ **不做子网扫描** |
| 不探测未在候选集中的地址 | 这是 ztio 与「扫描发现」的本质区别 |

> **这是设计选择，不是限制。** 候选由信令给出，所以**永远不需要扫描子网** ——
> 既避免了扫描观感，也避免了触发安全告警。

### T5 · 锚点被入侵

**场景**：攻击者控制锚点，篡改花名册，把 `phone` 解析到自己的地址。

| 措施 | 效果 |
|---|---|
| 锚点**只提供 ZT 地址**，不提供候选 | 攻击者仍需拿到有效 ZT 身份才能冒充 |
| 客户端缓存 + 异常变更告警 | 地址突然变化时提示用户 |
| 静态花名册（方式 A） | **攻击面最小** —— 没有可篡改的运行时状态 |

### T6 · 本地地址泄露到公网

**场景**：某次崩溃日志 / 分析上报带上了候选集。

| 措施 | 效果 |
|---|---|
| **候选集不写入任何日志** | 硬性要求 |
| 信令消息不落盘 | 内存中处理完即丢弃 |
| 诊断上报只含计数，不含地址 | 见 07 §7.8 |

## 9.4 隐私设计原则

| # | 原则 |
|---|---|
| P1 | **局域网拓扑不离开你自己的设备** —— 只在设备间经 ZT 加密链路交换 |
| P2 | **不引入公网发现服务** —— 减少数据外流面和运维负担 |
| P3 | **不扫描子网** —— 只探测信令给出的候选 |
| P4 | **不持久化候选集** —— 进程退出即丢弃 |
| P5 | **诊断只上报计数与状态，不上报地址** |
| P6 | **降级不静默** —— 用户有权知道当前走的是哪条路径 |

> **P1 是本方案相对「公网 rendezvous」最大的隐私优势。**
> rendezvous 方案要求每台设备把自己的内网 IP 上报到一台公网服务器 ——
> 那台服务器因此持有了整个内网拓扑。
