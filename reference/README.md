# reference · 参考实现

本目录用于放置 ztio 协议的参考实现。**目前为空** —— 协议尚在设计中，见 `../spec/`。

## 计划中的结构

```
reference/
├── sdk/            核心库（候选枚举 / 信令 / 探测 / 选路）
│   ├── candidates/ 接口枚举与过滤（平台相关）
│   ├── signaling/  消息编解码与状态机
│   ├── prober/     并行连通性检查
│   └── selector/   路径选择与降级
├── anchor/         锚点 / 花名册服务（方式 A 静态 + 方式 B 动态注册）
└── examples/       最小可运行示例
    ├── macos/      发起端
    └── ios/        应答端
```

## 实现优先级建议

| 序 | 模块 | 理由 |
|---|---|---|
| 1 | `anchor/` 静态花名册 | **零依赖，先让引导这一层跑起来** |
| 2 | `sdk/candidates/` | 核心难点在过滤规则（尤其是虚拟接口），见 spec 04 |
| 3 | `sdk/signaling/` | 协议正确性靠它，见 spec 05 |
| 4 | `sdk/prober/` + `selector/` | 并行探测与降级，见 spec 06 |
| 5 | `anchor/` 动态注册 | 设备数量增长后再做 |

## 第一个里程碑

**两端能各自枚举候选、经 ZT 交换、并在局域网内连上。**

这个里程碑同时验证了整条链路的两个关键假设：

1. ZT 链路在该网络下确实可用（哪怕经中继）
2. 局域网单播确实可达（即该 WiFi 没有开客户端隔离）

**失败即结论** —— 如果第 2 条不成立，整个局域网优先策略在该网络下不适用，
应直接记录为「该环境仅支持 ZT 路径」，而不是继续调优。

见 `../spec/06-path-selection.md` §6.4 的降级诊断表。
